# Signal Desk intelligence pipeline

The dashboard reads one public, versioned JSON snapshot from the `signal-data` branch. The scheduled GitHub Action runs three times daily. The same job checks official Render, GitHub Actions and Cloudflare limits on Mondays. It publishes only public source material and run receipts. The data branch is separate from `main`, so collection does not trigger a Render rebuild.

`GET /api/intelligence` is a read-only Glance endpoint. It fetches the fixed public snapshot URL, validates the full contract before accepting it (schema version, `generated_at`, `data_fresh`, and the required `sources`/`items`/`alerts`/`receipt` shapes, with future timestamps rejected), caches it in memory for 30 minutes with the network call performed outside the request lock, and serves a clear fallback when the branch is missing. If a fetch fails, validation fails, or a snapshot is over 12 hours old, it suppresses the Today brief, keeps only health pointers, and adds a delivery alert with the reason; failure causes are logged server-side. The endpoint strips the raw `cache` and `docs` fields before serving, so responses carry only what the cards render. Render sleep or redeploy resets this in-memory cache; nothing important is stored on Render's ephemeral filesystem. The four intelligence cards cache rendered HTML for 30 minutes so a stale verdict reaches the page promptly.

The snapshot contract is `schema_version: 1`, `generated_at`, `data_fresh`, `sources`, `items` (`radar`, `experiments`), `alerts`, `brief`, `docs`, `cache`, and `receipt`. `receipt` carries `input_count`, `unique_count`, `radar_count`, `experiment_count`, `excluded_count`, `failed_sources`, and `stale_sources`. Each brief line carries a `label`, `title`, `reason`, `published_at`, an internal `url`, and the dated `source_url` behind the recommendation. Source entries record status (`ok`, `stale`, `failed`), latest item, last success and input count; a failed source keeps its last-good cache and raises a health alert. Release matches require a phrase in source-authored notes and a matching project owner. Documentation text changes request human review; they do not assert a changed allowance.

## Rollout after authorization

1. Push the code to the public repository. Run the `Build Signal Desk intelligence snapshot` workflow manually once to create `signal-data`; allow Actions to write repository contents. No Render key is needed.
2. Confirm `snapshot.json` is public, schema 1, small (expected under 200 KB), and contains no private data or tokens. Check `/api/intelligence` and the four page fragments after the Render deploy.
3. Verify the first scheduled run updates `signal-data` without deploying `main`. Watch source failures for a week; tune freshness windows only with observed publisher cadence.

At nine feeds × up to 25 entries, three runs daily make at most 27 feed requests/day plus nine documentation requests on Mondays. The collector makes sequential requests with an 18-second timeout and a 2 MB response cap per source, and retries a transient failure once with a short backoff; deterministic errors such as the size cap are not retried. The Action has an eight-minute job timeout. The Glance endpoint makes at most one upstream snapshot request per 30-minute running interval. GitHub schedule delays, source blocking, changed RSS structure, noisy documentation diffs, and Render cold starts remain operational risks.
